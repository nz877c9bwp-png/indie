# 폰·태블릿 레이아웃 검증

검증일: 2026-09-10. 대상은 fork 미리보기의 `be5a537` HTML이다. 배포 HTML이 로컬 테스트 대상과 바이트 단위로 같은 것을 확인했다. 이번 검증에서는 애플리케이션 CSS·본문·폰트 크기를 변경하지 않았다. PR 준비 시 최신 main `44a48e3`을 통합한 `1485e94`에서도 기기 24개·레이아웃 66개 검사를 다시 실행해 모두 통과했다.

## 범위와 결과

`npm run test:devices`: **24/24 PASS**. 아래 12개 프로필 각각의 세로·가로 방향을 검사했다. 기기명은 Playwright 1.63.0 프리셋 이름이며 실제 기기의 물리 해상도와 동일하다는 뜻이 아니다. 브라우저 툴바·화면 배율에 따라 사용 가능한 CSS 화면 폭은 달라진다.

| 프로필 | 엔진 | 결과 |
| --- | --- | --- |
| iPhone 13 Mini, 16, 16 Pro, 16 Pro Max | WebKit | 8 PASS |
| Galaxy S24, Pixel 9 Pro XL | Chromium | 4 PASS |
| iPad Pro 11 | WebKit | 2 PASS |

| 대표 태블릿 화면 744×1133, 820×1180, 1032×1376 및 분할 창 600×900 (각 반대 방향 포함) | WebKit | 8 PASS |

- 문서·본문·게시글 표의 기본 배율 가로 넘침 없음.
- 빈 게시판과 글 있는 게시판의 각 열 너비 차이 1px 미만.
- 메뉴/HOT 내부 스크롤 후 메뉴·HOT·게시글 터치 이동 정상.
- 이미지·YouTube iframe, 앨범 목록·상세, 글쓰기·앨범 검색, 설정·약관·로그인·회원가입 모달 확인.
- runtime exception, console error, 예기치 않은 dialog 없음.
- iPad 가로, Galaxy Tab 세로, 큰 Android 폰 가로 스크린샷도 직접 확인했다.

기존 `npm run test:layout`도 **66/66 PASS**: Chromium/Firefox/WebKit의 320–1440px 범위, 긴 제목·닉네임·URL, 큰 이미지, 화면 전환, 회전, CSS 확대, 빈 게시판 비교를 재검증했다.

## 해석과 한계

840px 이하에서는 가로 메뉴·HOT 배치, 그보다 넓으면 기존 데스크톱 배치(왼쪽 메뉴)가 나타난다. 큰 폰의 가로 화면이나 태블릿에서 이 전환은 정상 동작이다. 데스크톱 전환 직후의 비교적 좁은 화면에서는 표의 분류 등 짧은 열도 줄바꿈될 수 있다. 표시 누락이나 가로 넘침은 확인되지 않았다.

실제 iPhone 16 Pro는 사용자가 양호하다고 확인했다. 나머지는 브라우저 엔진 기반 에뮬레이션이며 실제 Samsung Internet/Safari 앱, OS별 글자 확대, 화면 안전 영역, 주소창 이동, 가상 키보드, 손가락 pinch 및 기기 성능까지 보장하지 않는다. 외부 폰트·Supabase·이미지·YouTube·검색 요청은 mock으로 대체했으므로 실제 폰트 로딩과 동영상 재생 검증은 아니다. 운영 DB에 테스트 데이터를 쓰지 않았다.
