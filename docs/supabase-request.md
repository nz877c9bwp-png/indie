## 1. 신고 테이블 만들기 (SQL Editor에서 아래 그대로 한 번 실행)

앱스토어 심사 요건(사용자 생성 콘텐츠 신고 기능) 때문에 필요합니다. 기존 테이블은 건드리지 않고 `reports` 테이블만 새로 만듭니다. 여러 번 실행해도 안전합니다.

```sql
-- 신고 (앱스토어 심사 지침 1.2): 게시글/댓글 신고를 앱 안에서 접수한다. 로그인 사용자만 넣을 수 있고
-- 읽기는 관리자만(Supabase 대시보드 Table Editor에서 확인). 처리한 신고는 행을 지우면 된다.
create table if not exists public.reports (
  id bigint generated by default as identity primary key,
  target_type text not null check (target_type in ('post', 'comment')),
  target_id bigint not null,
  reason text,
  reporter_id uuid references auth.users(id) on delete set null,
  created_at timestamptz not null default now()
);
alter table public.reports enable row level security;
drop policy if exists "reports insert" on public.reports;
drop policy if exists "reports admin read" on public.reports;
create policy "reports insert" on public.reports for insert to authenticated
  with check (auth.uid() = reporter_id);
create policy "reports admin read" on public.reports for select to authenticated using (public.is_admin());

notify pgrst, 'reload schema';
```

실행 후 Table Editor에 `reports` 테이블이 보이면 끝입니다. 신고가 들어오면 이 테이블에 쌓이고, 처리한 건은 행을 지우시면 됩니다.

## 2. Apple 로그인 프로바이더 켜기 (Authentication → Providers → Apple)

앱스토어 심사 지침 4.8 때문에 카카오 로그인이 있는 앱은 Apple 로그인도 꼭 있어야 합니다. 값은 제가 Apple 개발자 계정에서 만들어서 드리겠습니다.

- Enable Sign in with Apple: **ON**
- Client IDs: `kr.duli.web,kr.duli.app`
- Secret Key (for OAuth): 제가 따로 보내드리는 JWT 문자열 붙여넣기
- 저장

이 Secret Key는 Apple 규정상 최대 6개월마다 새로 만들어야 해서, 만료 전에 제가 새 값을 다시 드리면 같은 자리에 교체만 해주시면 됩니다.
